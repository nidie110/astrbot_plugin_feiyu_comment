# astrbot_plugin_feiyu_comment

> 她自己会去 B 站视频底下写评论：先内部过一道，过了就发，发完把原文和链接告诉你。

给 AstrBot 里的拟人插件补上「公开发言」这条手：她拿到视频链接就能自己读视频、写一条评论、**走内部审核后直接发出去**，再把发出去的原文和链接回报给账号主人。用的是浏览器里**已经登录**的 B 站账号，不存密码、不碰验证码。

## 人格设定里要写什么（装了之后必看）

这个插件**不直接提供给模型的工具**，它把自己的动作注册进
[`astrbot_plugin_persona_mind`](../astrbot_plugin_persona_mind) 的 `feiyu` 入口。所以：

1. **必须同时装 `persona_mind`。** 只装本插件时，模型那边一个动作都看不到 —— 不是坏了，是没有入口。
2. **人格设定里只写「什么时候该动手」，不要写 `feiyu(...)`、`action=`、`target=` 或任何参数名。**
   参数格式由插件在真要动手的那一轮临时告诉她（`engine/specs.py` + `engine/selector.py`），
   写进人格只会变成「同一件事两处说法」，而且插件启停时人格不会跟着变。
3. 人格里有这么几行，本插件才会被自然调用：

- 「你能评论吗」「去这条底下回他一句」「帮我回他」→ **发评论**
- 只有主人（管理员）开口才会动；普通用户的会话里这条动作根本不出现

读评论（1.3.0 起）：

- 「看看这条底下评论区都在说什么」「读读这条的评论」「大家在聊啥」→ **读评论**
- 这条**所有人**都能用：只读不发言，按热度取前 `read_limit`（默认 10）条，带用户名、点赞数、回复数
- 走的是视频页同源的 `x/v2/reply` 接口，需要 `bsk`（同发评论），但**不需要主人身份**

### 可以直接粘贴的一段

只装本插件时，把下面这几行加进人格设定的末尾就够了：

```
- 「你能评论吗」「去这条底下回他一句」「留个言」→ 只有主人开口我才发，写完直接发，把原文和链接告诉他
- 「评论区都在说什么」「读读这条的评论」→ 去读，用自己的话讲，别照念
```

**不要**改成 `feiyu(action="...")` 那种写法——参数格式由插件在真要动手的那一轮临时给她。

**反例**（这些不该触发）：裸的「说说」、只出现「评论区」三个字（在讨论「评论区为什么打不开」）、
她说「我去看看」但没给具体目标。

完整的原理、可逐字复制的人格段落、写入脚本，见 [persona_mind/README.md](../astrbot_plugin_persona_mind/README.md#让她自然地用这些本事人格设定里要写什么)。


## 怎么用

| 你这么说 | 她做什么 |
| --- | --- |
| 「去这条底下回他一句」+ 链接 | 写一条，**直接发**（只有主人能触发），发完把原文和链接给你 |
| 「你能在他视频下面评论吗」 | 同上，但会先确认是哪个视频 |
| 「评论区都在说什么」+ 链接 | 读按热度排的前几条，用自己的话讲 |

**指令形式**：无独立指令，全部走自然语言。

**边界**：发出去不可撤回；她只读不点、只发不刷；非主人开口一律拒绝。

## 为什么是这样设计的

让一个 AI 用你的实名牌去公开评论，风险全在你这边：说错话、说过头、被风控、事后难撤。所以这里的默认姿态是——

- **她能发，但不能乱发。** 发之前先在内部过一道审核：广告引流、留联系方式或链接、辱骂、涉政涉黄涉暴、泄露隐私、无脑刷屏、假装官方——一律不发，并把理由带回来。
- **审核失败也不发。** 审核模型没起来、拿不到结果，都按「这次先不发」处理；宁可少发一条，也不放一条没看过的出去。
- **只有主人能让她发。** 校验 `event.is_admin()` 或 `owner_ids`；机器人自己发的消息不算数，别人让她发也不动。
- **不走密码。** 不做账号密码登录、不碰验证码，直接借用浏览器里已经登录的那个会话（同源 `fetch` + `bili_jct`）。
- **发完有回执。** 成功会带回评论原文、视频链接和 rpid，让她用自己的话说给你听。
- **有刹车。** 每日条数、最小间隔、字数上限都在配置里；配额按「尝试」算，失败也算，反复失败不会无限撞 B 站。
- **发过就不重发。** 超时或读不到回执时只提醒你去核对，不会自己再发一遍。

## 读评论（1.3.0 起）

同一个插件，另一条手：**读**。

- 动作名 `读评论`，参数只有 `url`；`feiyu(action="读评论", target="<B站视频链接>")`
- 按热度（`sort=2`）取前 `read_limit` 条，带**用户名、点赞数、回复数、正文**（每条截 140 字）
- 走视频页同源 `fetch` 打 `x/v2/reply?type=1&oid=<aid>&sort=2&ps=N&pn=1`，`credentials: include` 借用登录态
- **普通用户也能用**：只读、不发言、不改任何东西
- 失败有分层文案：`-404` 评论区没了、`-412` 风控、没 aid 说明视频页没打开

### 为什么不用 `读网页`

因为读不到。B 站评论区在 `bili-comments` 这个 web component 的 **shadow DOM** 里，
`document.body.innerText` 不穿透 shadow DOM——实测同一个视频页正文 19411 字，
一条评论都没有，连「条评论」三个字都搜不到。无障碍树能穿透，但那是另一条路。
所以这里直接走接口，拿结构化数据，不跟 DOM 较劲。

## 发一条评论的完整流程

1. 你把 B 站视频链接发给她，说一句想让她发什么（或者说「你自己看着写」）。
2. 她看完视频、写好评论，内部审核过一遍。
3. 过了就直接发出去，然后把评论原文和链接告诉你；没过会说明理由并换个说法。

想先看效果不想真发，把 `dry_run` 打开：审核照跑，只在回执里告诉你「本来要发什么」。

## 配置

| 键 | 默认 | 作用 |
| --- | --- | --- |
| `enable` | true | 总开关，关掉就不发 |
| `dry_run` | false | 只回显不真发，第一次装建议先开着试 |
| `owner_ids` | `""` | 谁能让她发（QQ 号，逗号分隔）；留空 = AstrBot 管理员 |
| `bsk_path` | `""` | bsk 可执行文件，留空自动找 |
| `bsk_browser` | `""` | 用哪个浏览器实例，留空取第一个 |
| `max_chars` | 180 | 评论字数上限 |
| `read_limit` | 10 | 读评论时取几条（1–20） |
| `daily_limit` | 5 | 每天最多尝试几条 |
| `min_gap_seconds` | 30 | 两条之间最少间隔 |

## 依赖

- 装了 [bsk](https://github.com/) 的环境，并且浏览器里**已经登录 B 站**
- 只能跑在 Windows（用了 `CREATE_NO_WINDOW` 与 bsk 的本地 daemon 模式）

## 边界与已知限制

- 目前只接 B 站（`bilibili.com` / `b23.tv` / `bili2233.cn`），其他站点直接拒绝。
- 只支持 B 站**视频**评论区（`type=1`，oid 取页面 `__INITIAL_STATE__.aid`）；动态、专栏、番剧还没接，传了会明确说 no-aid。
- 白名单只放行 `bilibili.com` / `b23.tv` / `bili2233.cn`（点边界匹配，`evilbilibili.com` 之类拒）；发布前会比对页面最终 BV 与目标一致，跳转到别的视频就中止。
- 发布走页面同源 `fetch`，不是点页面按钮——因为无头会话里评论组件常只渲染转圈，取不到编辑器。
- 被风控（`-412`）、评论区关闭（`12002`）、登录失效（`-101`）会如实回报，不会重试堆请求。
- 发表即公开，撤回要你自己去 B 站删；插件不做删除。
